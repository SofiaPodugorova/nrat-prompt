# NRAT: поиск ОК, скачивание PDF и годовой архив

Проект собирает только «Облікові картки ДіР» / «Облікові картки НДДКР»
(`typeSearch2=ok`). Основной ключ — `doc_id`. Год датасета ещё не выбран:
параметр `--year` обязателен. Извлечение полей из PDF и таблицы пока не реализовано.
Готовые аналогичные реализации не использовались.

## Установка в Windows PowerShell

Нужны Python 3.10+ и Git. Из актуальной папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Активация окружения и изменение ExecutionPolicy не нужны. Установка зависимостей
требует сети. Все тесты локальные: HTML, ответы и PDF-байты искусственные,
а не сохранённые ответы НРАТ. Реальные ожидания заменены управляемыми часами.

В GitHub пока может находиться более старый этап. До загрузки всей разработки
используйте актуальную переданную папку/историю коммитов; не заменяйте её старой
копией `main`. Отправка в GitHub отложена до завершения проекта.

## Команды для будущей проверки

**Команды этого раздела обращаются к НРАТ.** Они не запускались в рамках
локальной разработки. Перед живой проверкой на ноутбуке подключите мобильную
сеть, если она нужна для доступа. Сеть ноутбука не меняет сеть удалённой среды.
`2010-03-12` — диагностический день, не выбор года будущего датасета.

Только метаданные одной страницы, без PDF:

```powershell
.\.venv\Scripts\python.exe -m nrat --date 2010-03-12 --page 1
```

Только метаданные всех страниц одного дня, без PDF:

```powershell
.\.venv\Scripts\python.exe -m nrat day --date 2010-03-12
```

Результат этой команды: `data/days/2010-03-12.json`. Она начинает новый обход
с страницы 1 и заменяет файл; возобновление относится к команде `collect`.

Следующая небольшая проверка: все страницы одного дня и максимум **три уникальных
документа для скачивания**, каждый с максимум тремя попытками:

```powershell
.\.venv\Scripts\python.exe -m nrat collect --year 2010 --day 2010-03-12 --max-downloads 3 --work-dir .\data\check-2010
```

Один день со скачиванием всех найденных PDF:

```powershell
.\.venv\Scripts\python.exe -m nrat collect --year 2010 --day 2010-03-12 --work-dir .\data\check-2010
```

Повтор той же команды продолжает работу в той же папке. Проверенные файлы
пропускаются, незавершённые загрузки повторяются. При снятии лимита уже
найденные документы и история сохраняются. `--max-downloads 0` разрешает
разобрать выдачу первого требующего обработки дня без новых PDF-загрузок.
После достижения лимита новых операций обход останавливается, чтобы не
расширять диагностический запуск на весь год. Пропуски корректных файлов
и подтверждённые 404/410 лимит не расходуют.

Годовой сбор: **сначала выберите год**, затем выполните:

```powershell
$datasetYear = Read-Host "Введите выбранный год датасета"
.\.venv\Scripts\python.exe -m nrat collect --year $datasetYear --work-dir ".\data\$datasetYear"
```

Для возобновления после остановки запустите **ту же команду с тем же годом и
папкой**. Новый год требует другой рабочей папки. Автоматически обходятся
365 или 366 дней, включая 29 февраля. Незавершённая выдача начинается с
`pa=1`, прежние документы и ошибки не удаляются. Подтверждённые 404/410
считаются учтённым отсутствием и повторно автоматически не проверяются.

`--no-archive` оставляет отчёты и чекпоинт без создания ZIP. Не запускайте
несколько процессов сбора одновременно с одной рабочей папкой.

## Файлы результата

По умолчанию `collect` использует `data/ГОД/`, относительно текущей папки:

| Файл | Содержимое |
| --- | --- |
| `checkpoint.json` | Авторитетное состояние: документы, варианты, дни, история ошибок и запусков |
| `days/ДАТА.json` | Последний обход выдачи за день, включая страницы, повторы, счётчики и проблемы |
| `pdf/doc_id.pdf` | Проверенные исходные PDF; имя не содержит номера из выдачи |
| `manifest.json` | Все найденные `doc_id`, исходные метаданные, все даты обнаружения и варианты; размеры, SHA-256 и конечные URL сохранённых PDF |
| `summary.json` | Раздельная полнота выдачи, обработка документов, наличие PDF, количества и незавершённые даты |
| `unavailable.csv` | Только подтверждённые HTTP 404/410 источника PDF |
| `unresolved.csv` | Все найденные документы с текущими незавершёнными статусами |
| `unfinished_dates.csv` | Незавершённые даты, проблемы полноты выдачи и загрузок |
| `errors.csv` | Общая накопленная история ошибок, включая неудачи перед успешным повтором |
| `search_errors.csv` | Ошибки поисковой выдачи отдельно от PDF |
| `http500.csv` | Одна строка на каждый документ, хотя бы раз вернувший HTTP 500 при скачивании |
| `nrat-ГОД-complete.zip` / `nrat-ГОД-partial.zip` | Проверенный архив; статус также явно записан внутри |

CSV записываются в UTF-8 с BOM, JSON — в UTF-8 с украинским и английским
текстом. `listing_number` в JSON всегда строка; CSV также содержит исходное
текстовое значение. При импорте CSV в Excel задайте для номеров тип **Text**,
чтобы Excel самостоятельно не удалил начальные нули.

`http500.csv` содержит исходные метаданные, варианты и даты обнаружения,
`total_attempts`, `http500_count`, `first500_at`, `last500_at`, текущий `status`.
Число попыток накоплено между запусками, включая успешные; 500 сохраняются
после `ok` и `skip`. `last_error` — последняя историческая ошибка, а не
утверждение о текущем неуспехе. Ошибки выдачи в этот CSV не попадают.
В `errors.csv` есть время UTC, дата запроса, категория, номер попытки,
HTTP-код/тип исключения, исходный номер, `doc_id`, причина и URL. Сырые тела
аварийных ответов, cookies, токены и заголовки сессии не экспортируются.

Чекпоинт сохраняется после каждой страницы, перед PDF-попыткой, после
неудачной попытки и обработки документа. Запись идёт во временный файл
в той же папке, с `flush`, `fsync` и атомарным `os.replace`.
Повреждённый JSON, несовместимая схема/год, противоречивое завершение или
опасные пути вызывают ошибку: состояние не сбрасывается. Отсутствующий
чекпоинт при наличии прежних данных также требует восстановления состояния,
а не молчаливого создания новой истории. Не удаляйте чекпоинт для повторного
запуска. При полном сбое диска сохраняется последний успешный атомарный снимок.
Ctrl+C сохраняет доступный прогресс и отметку остановки. При аварийном
завершении может остаться `.part` или временный файл; при повторной загрузке
`.part` перезаписывается, а окончательный файл проверяется заново.

## Полнота

Три независимых признака в `summary.json`:

- `search_complete`: каждый календарный день года имеет подтверждённую
  полную выдачу; счётчики сверены, нет `partial`, повторов страниц или ограничений.
- `processing_complete`: все найденные документы имеют `ok`, `skip` или
  подтверждённый `notpdf`. Это не подтверждает отсутствие ненайденных документов.
- `all_found_pdfs_present`: для всех найденных документов имеются проверенные PDF.

`accounted_collection_complete` допускает подтверждённые 404/410, если весь
год обойдён и обработан. Однако `status=complete` и архив `complete` требуют
**всех трёх признаков**, обычного годового запуска без ограничений и отсутствия
остановки. HTTP 404/410 сохраняются видимыми; набор с отсутствующими PDF
упаковывается как `partial`. Один день и любой запуск с `--max-downloads`
никогда не объявляются полным годовым сбором.

День считается учтённым завершённым, когда выдача полная и все обнаруженные
для него документы обработаны (`ok`/`skip`/`notpdf`). Неустранённые ошибки
оставляют день незавершённым. Подтверждённый нулевой день — нормальный результат.

Для поиска сохраняются `page_fail`, `count_missing`, `page_repeat`,
`page_limit` (100 страниц, а следующая существует), `count_mismatch`,
`count_changed`, `partial`, `pagination_mismatch`, `result_limit`,
`count_ge_1000`, конфликты метаданных. Страница с малым числом карточек
сама по себе не считается последней. История исправленных HTTP-ошибок не
мешает подтверждению полноты, но остаётся в журнале.

Коды выхода `collect`: `0` — полный годовой набор, `2` — неполный/ограниченный,
`130` — Ctrl+C, `1` — повреждённый чекпоинт, ошибка хранения или архива.
Для диагностического одного дня нормален код `2`: это не годовой набор.

## Скачивание и HTTP

| Параметр | Значение |
| --- | --- |
| Между запросами поиска | Не менее 3 секунд |
| Между запросами PDF | Не менее 1 секунды, включая безопасные переходы |
| Первый запрос новой даты | Не менее 5 секунд после предыдущего сетевого ответа |
| Таймаут поиска | Соединение 30 секунд, чтение 90 секунд |
| Таймаут PDF | Соединение 30 секунд, чтение 120 секунд |
| Повторы | Всего три попытки, ожидания 15 и 30 секунд |
| Числовой `Retry-After` | Большее из обычной паузы и значения заголовка, максимум 300 секунд |

Чтение — таймаут ожидания очередных данных, а не общий предел загрузки.
Все запросы одного клиента последовательные. Повторное обнаружение одного
`doc_id` на другой странице/дате не создаёт новый бюджет загрузки в текущем
запуске. Бюджет повторных попыток PDF реализован в клиенте; внешних повторов
поверх него нет. Следующий запуск может повторить незавершённый документ.

Источник — фактический `source_url` из выдачи. Исходный домен не заменяется.
До окончательного переименования `.part` проверяется на непустой ответ и
сигнатуру `%PDF`; затем сохраняются размер и SHA-256. `skip` возможен только
при совпадении сигнатуры, размера и хеша с чекпоинтом. Корректный по сигнатуре
файл без сохранённого хеша не принимается автоматически.

Разрешено максимум три перенаправления в одной попытке, только HTTPS на
`nddkr.ukrintei.ua` или `dir.ukrintei.ua`, без userinfo, порта, query и fragment.
Это сознательное ограничение: перенаправление, требующее параметров URL,
будет ошибкой и потребует отдельной проверки. Конечный адрес сохраняется.
Перенаправления поисковой страницы не выполняются автоматически.

| Статус PDF | Значение |
| --- | --- |
| `ok` | Скачан и прошёл первичную проверку |
| `skip` | Проверен существующий файл и его размер/SHA-256 |
| `notpdf` | Только HTTP 404/410 от разрешённого источника PDF; без повторов |
| `server500` | Последняя неустранённая ошибка после трёх попыток — HTTP 500 |
| `empty` | Последняя неустранённая ошибка после повторов — пустой ответ |
| `fail` | Остальные неустранённые ошибки |
| `pending` | Ещё не обработан либо операция прервана |

HTTP 500, другие 5xx, 408/425/429, сеть, таймауты, пустые и неподходящие
ответы повторяются. Непустой HTML имеет отдельную причину `html_instead_pdf`;
он не переименовывается в `.pdf`. Ошибка диска — `disk_error`, без сетевых
повторов. Остальные ошибочные HTTP-ответы терминальны в текущем запуске.
Ни один ответ поисковой страницы не подтверждает отсутствие PDF.

## Проверка архива

ZIP создаётся временно и включает только проверенные PDF, весь манифест,
сводку и восемь перечисленных файлов отчётов. До окончательного переименования
проверяются CRC, отсутствие повторных/лишних записей, точное совпадение набора
PDF с манифестом, его содержимое, сводка, сигнатуры, размеры и SHA-256 PDF.
Ошибка оставляет прежний архив и рабочие PDF доступными. Рабочие PDF не удаляются.
Частичный архив сохраняет также записи документов без файла.

## Правила разбора и ограничения

Запрос поиска: `https://nrat.ukrintei.ua/searchdb/`, `typeSearch2=ok`, одинаковые
`dateFromSearch`/`dateToSearch`, явный `pa`, `sortOrder=registration_date`,
`sortDir=asc`, `tab=big`. Проверяются форма, даты и активный номер страницы;
пагинация должна двигаться вперёд и сохранять параметры.
Селекторы: `.my-card`, `.typeBase`, `.my-card-body`,
`.page_control .page_info`, `.pagination`. Повторяющиеся счётчики должны совпадать.
Пустой день требует корректных фильтров, явного 0 и отсутствия карточек/пагинации.

`doc_id` — 32 hex из `/view/ok/<doc_id>` на доменах источника.
`/searchdoc/<номер>/` и атрибут кнопки `.view_card` для ключа не используются.
`listing_number` — исходный номер без предположения о его юридической роли.
`query_date` — дата запроса, а не извлечённая дата регистрации карточки.
Государственный учётный и регистрационный номера позже будут извлекаться
раздельно из PDF. Варианты метаданных и все даты обнаружения сохраняются;
несколько карточек одной работы не объединяются по номеру.

Первичная проверка не доказывает читаемость всех страниц PDF; это задача
следующего этапа. Один основной файл на `doc_id`: варианты метаданных
сохраняются, исторические версии самих PDF пока отдельно не коллекционируются.
Не проверены живым запуском: реальные PDF-ответы/перенаправления, устойчивость
сортировки при равных датах и структуры выдачи разных лет.

## Модули и Git

- `http.py`, `search.py` — последовательный клиент и парсер выдачи.
- `day.py` — дневной обход с проверками и уведомлением о сохранённых страницах.
- `download.py` — `.part`, первичная проверка и проверка существующего файла.
- `state.py`, `collector.py` — проверяемый чекпоинт и возобновляемый обход года.
- `reports.py`, `archive.py` — отчёты и проверка ZIP.
- `__main__.py` — команды страницы, дня и `collect`.
- `tests/` — искусственные сценарии без сети.

Код, тесты и документация — в Git. PDF, ZIP, CSV/XLSX, HTML, журналы,
чекпоинты, временные файлы, cookies и токены исключены через `.gitignore`.
Не используйте `git add -f` для результатов сбора.
