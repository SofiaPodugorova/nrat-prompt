# NRAT: метаданные ОК за одну страницу или день

Последовательное получение и проверка выдачи `НДДКР ОК`: одна страница или
все страницы одной явно заданной даты. Год датасета не выбран. PDF,
дополнительные HTML-карточки и другие даты не запрашиваются.
Готовые аналогичные реализации не использовались.

## Установка в Windows PowerShell

Нужен Python 3.10 или новее и Git. Выполните в папке для проектов:

```powershell
git clone https://github.com/SofiaPodugorova/nrat-prompt.git
Set-Location nrat-prompt
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Активация окружения и изменение ExecutionPolicy не требуются.
Тесты не обращаются к сети. `tests/examples.py` содержит **искусственный HTML**,
а не сохранённые ответы НРАТ. Установка зависимостей требует сети.

## Запуск одной страницы

Команда ниже выполняет живой запрос к НРАТ. Перед запуском на ноутбуке
подключите мобильную сеть, если она необходима для доступа. Сеть ноутбука
не влияет на удалённую среду ChatGPT. Дата примера диагностическая, это не
выбор года будущего датасета.

```powershell
.\.venv\Scripts\python.exe -m nrat --date 2010-03-12 --page 1
```

Дата и страница обязательны. JSON выводится в консоль; украинский текст
представлен обратимыми `\u`-последовательностями для совместимости с Windows.
Код выхода: `0` — разбор завершён, `2` — есть проблемы отдельных карточек,
`1` — ошибка получения/валидации страницы. При ошибке JSON содержит причину,
HTTP-код при наличии и номер каждой неудачной попытки, включая ошибки перед
успешным повтором. Тела ответов, cookies и токены в вывод не включаются.

Используемые параметры: `typeSearch2=ok`, одинаковые `dateFromSearch` и
`dateToSearch`, явный `pa`, `sortOrder=registration_date`, `sortDir=asc`,
`tab=big`. Адрес: `https://nrat.ukrintei.ua/searchdb/`.

## Дневной обход из Windows PowerShell

**Следующая команда обратится к сайту НРАТ**, начиная с `pa=1`, и обойдёт
страницы только за 12 марта 2010 года. Подключите мобильную сеть на ноутбуке,
если она нужна для доступа. Дата диагностическая; год датасета не выбран.

```powershell
.\.venv\Scripts\python.exe -m nrat day --date 2010-03-12
```

Результат: `data/days/2010-03-12.json` относительно текущей папки. При необходимости:

```powershell
.\.venv\Scripts\python.exe -m nrat day --date 2010-03-12 --output .\data\diagnostic-day.json
```

JSON сохраняется в UTF-8 с украинским текстом. `data/` и `*.json` исключены из
Git. Не добавляйте результаты через `git add -f`. Файл записывается после
каждой страницы и неудачной HTTP-попытки через временный файл в той же папке,
`flush`, `fsync` и атомарный `os.replace`. Если запись/замена не удалась, старый
корректный JSON остаётся доступным, а запуск завершается ошибкой записи.

Каждый запуск начинает новый обход с страницы 1 и заменяет результат по
указанному пути. Автоматического возобновления пока нет; для сохранения
результатов нескольких запусков используйте разные `--output`.

### Полнота дневного результата

`status=complete` означает: пагинация закончилась, счётчик не менялся,
количество уникальных `doc_id` совпало со счётчиком, все страницы разобраны,
нет ограничения выдачи, порога 1000 или конфликтов номера/ссылки.
Подтверждённый нулевой день также `complete`.

`status=incomplete` сохраняет все уже найденные документы и конкретные
`incomplete_reasons`. Во время незавершённого обхода причина — `in_progress`.
Возможные итоговые причины:

| Категория | Значение |
| --- | --- |
| `page_fail` | Страница не получена/не прошла проверку; история попыток сохранена отдельно |
| `page_repeat` | Следующая непустая страница не добавила новых `doc_id` |
| `page_limit` | Обработаны 100 страниц, а следующая ещё существует |
| `count_mismatch` | Уникальные `doc_id` не совпали с первым счётчиком сайта |
| `count_changed` | Счётчик изменился между страницами; сохранены все наблюдённые значения |
| `partial` | Не все карточки страницы разобраны; доступны сведения о каждой проблеме |
| `pagination_mismatch` | Номер/дата ответа неверны либо следующий переход теряет параметры |
| `result_limit` | Сайт явно сообщает об ограничении выдачи |
| `count_ge_1000` | Счётчик не меньше 1000; полнота не подтверждается даже при совпадении количества |
| `metadata_conflict` | Для одного `doc_id` встретились разные исходные номера или ссылки |
| `interrupted` | Остановка через Ctrl+C; найденные карточки сохранены |
| `collection_error` | Неожиданная ошибка; сохраняется её тип без сырого сообщения/данных сессии |

На повторе страницы, `partial`, изменении счётчика или сбое обход останавливается.
При ограничении или конфликте можно дойти до конца пагинации, но статус остаётся
`incomplete`. Короткая страница сама по себе не считается последней.

Структура JSON:

- `query_date`, `search` — дата запроса, адрес и начальные параметры;
  дата запроса не является извлечённой датой регистрации.
- `reported_count`, `reported_counts`, `unique_count` — первый счётчик,
  счётчики по страницам и найденные уникальные идентификаторы.
- `records` — одна исходная запись на `doc_id`; номер остаётся строкой.
- `pages`, `pages_processed` — параметры и статус каждой страницы, число
  попыток, карточек, новых документов, повторов, проблемы и следующий URL.
- `repeat_count`, `repeats`, `conflicts` — число повторных появлений, их
  наблюдения и обе версии конфликтующих метаданных. Первая запись не перезаписывается.
- `http_attempt_errors` — все неудачные попытки **поисковых страниц**, включая
  исправленные повтором. Исправленная ошибка не мешает статусу `complete`.
- `errors`, `incomplete_reasons`, `status`, `pagination_finished`,
  `limited`, `count_ge_1000`, `empty_day_confirmed`, `interrupted`, `updated_at`.

Код выхода дневной команды: `0` — полнота подтверждена, `2` — неполный сбор,
`130` — Ctrl+C, `1` — ошибка сохранения JSON. При принудительном завершении
процесса остаётся последний атомарно сохранённый снимок со статусом `incomplete`.
Это прогресс текущего запуска, а не механизм возобновления.

## Python API

### API одной страницы

```python
from datetime import date
from nrat.http import HttpClient
from nrat.search import fetch_page

with HttpClient() as client:
    result = fetch_page(client, date(2010, 3, 12), 1)
    if result.value is not None:
        page = result.value
        print(page.total_count, page.parsing_complete, page.issues)
```

Используйте один `HttpClient` для последовательных запросов: он выдерживает
минимум 3 секунды после предыдущего ответа в пределах даты и 5 секунд при
смене даты. Отдельные процессы не разделяют таймер; при ручных повторных
запусках соблюдайте эти паузы самостоятельно. Дневной обход использует тот же
клиент и таймер; дополнительных ожиданий поверх повторных попыток не добавляет.

Дневной API:

```python
from pathlib import Path
from nrat.day import collect_day

with HttpClient() as client:
    result = collect_day(client, date(2010, 3, 12), Path("data/days/2010-03-12.json"))
```

Таймауты Requests: соединение 30 секунд, ожидание чтения 90 секунд (это не
общий предел длительности загрузки). Максимум три попытки: ожидания 15 и
30 секунд. Числовой `Retry-After` увеличивает ожидание до указанного значения,
максимум 300 секунд. Повторяются сетевые ошибки, HTTP 408/425/429/5xx,
пустой/не-HTML ответ и ошибки проверки HTML. Остальные HTTP-ответы, включая
404/410 и перенаправления, возвращаются как `page_fail` без повторов.
Перенаправления не выполняются автоматически, чтобы исключить запросы иных
ресурсов. Никакой HTTP-ответ выдачи не означает подтверждённое отсутствие PDF.

## Результат и проверки

- `records`: `doc_id`, исходный `listing_number`, фактический `source_url`,
  `title`, `description`, `query_date`. Номера всегда строки. `source_url`
  пока не является проверенным адресом PDF. `query_date` — дата запроса,
  а не извлечённая дата регистрации. Роли номеров не предполагаются.
- Идентификатор берётся только из HTTPS-ссылки с доменом `nddkr.ukrintei.ua`
  или `dir.ukrintei.ua` и путём `/view/ok/<32 hex>`. Допускается завершающий `/`.
  Ссылки с query/fragment, портом или userinfo отклоняются, чтобы не экспортировать
  возможные данные сессии. Домен фактического URL сохраняется.
- Проверяются `.my-card`, `.typeBase`, `.my-card-body`,
  `.page_control .page_info` и `.pagination`. Тип формы подтверждается
  `option[selected]` и/или фактическим способом NRAT `var typeSearch2='ok'`.
  JavaScript не исполняется; все найденные подтверждения должны совпадать.
- Повторяющиеся счётчики должны совпадать. Противоречия с карточками,
  пагинацией и фильтрами вызывают понятную ошибку. Ошибочная карточка остаётся
  в `issues` с порядковым номером и описанием; `parsing_complete=false`.
- `current_page`, `next_page_url` возвращаются, но следующий URL не запрашивается.
  Он проверяется на сохранение фильтров/сортировки/номера и нормализуется к
  `/searchdb/`; параметры сессии не экспортируются.
- `limited` обозначает явный `.limited_search`; `count_ge_1000` отдельно
  отмечает счётчик не менее 1000. Оба предупреждения включаются в `warnings`.
- `empty_day_confirmed=true` требует корректных фильтров, счётчика 0 и
  отсутствия карточек/пагинации. `parsing_complete` относится только к текущей
  странице и ничего не утверждает о полноте дня или года.

Остаётся проверить на следующих этапах: устойчивость сортировки при одинаковых
датах, варианты структуры HTML разных лет, юридическое значение даты и роли
номеров. Механизмы годового сбора и скачивания PDF здесь не реализованы.
Полнота дневного JSON относится только к поисковым метаданным.

## Структура

- `src/nrat/http.py` — таймауты, повторные попытки, паузы и история ошибок.
- `src/nrat/search.py` — модели результата, проверки и чистый разбор HTML.
- `src/nrat/day.py` — дневной обход, проверка полноты и атомарный JSON.
- `src/nrat/__main__.py` — команды страницы и дневного обхода.
- `tests/` — локальные тесты с искусственным HTML и подставным HTTP-клиентом.

PDF, ZIP, таблицы, HTML-ответы, логи, чекпоинты и данные сессии исключены из Git.
