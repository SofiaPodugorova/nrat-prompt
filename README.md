# NRAT: одна страница выдачи ОК

Первый рабочий этап: последовательный HTTP-запрос одной страницы дневной
выдачи `НДДКР ОК` и проверка её HTML. Год датасета не выбран.
PDF, дополнительные HTML-карточки, следующие страницы и другие даты
автоматически не запрашиваются. Готовые аналогичные реализации не использовались.

## Установка в Windows PowerShell

Нужен Python 3.10 или новее и Git. Выполните в папке для проектов:

```powershell
git clone https://github.com/SofiaPodugorova/nrat-prompt.git
Set-Location nrat-prompt
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Активация окружения и изменение ExecutionPolicy не требуются.
Тесты не обращаются к сети. `tests/examples.py` содержит **искусственный HTML**,
а не сохранённые ответы НРАТ. Установка зависимостей требует сети.

## Запуск одной страницы

Команда ниже выполняет живой запрос к НРАТ. Перед запуском на ноутбуке
подключите мобильную сеть, если она необходима для доступа. Сеть ноутбука
не влияет на удалённую среду ChatGPT. Дата примера диагностическая, это не
выбор года будущего датасета.

```powershell
.\.venv\Scripts\python.exe -m nrat --date 2010-03-12 --page 1
```

Дата и страница обязательны. JSON выводится в консоль; украинский текст
представлен обратимыми `\u`-последовательностями для совместимости с Windows.
Код выхода: `0` — разбор завершён, `2` — есть проблемы отдельных карточек,
`1` — ошибка получения/валидации страницы. При ошибке JSON содержит причину,
HTTP-код при наличии и номер каждой неудачной попытки, включая ошибки перед
успешным повтором. Тела ответов, cookies и токены в вывод не включаются.

Используемые параметры: `typeSearch2=ok`, одинаковые `dateFromSearch` и
`dateToSearch`, явный `pa`, `sortOrder=registration_date`, `sortDir=asc`,
`tab=big`. Адрес: `https://nrat.ukrintei.ua/searchdb/`.

## Python API

```python
from datetime import date
from nrat.http import HttpClient
from nrat.search import fetch_page

with HttpClient() as client:
    result = fetch_page(client, date(2010, 3, 12), 1)
    if result.value is not None:
        page = result.value
        print(page.total_count, page.parsing_complete, page.issues)
```

Используйте один `HttpClient` для последовательных запросов: он выдерживает
минимум 3 секунды после предыдущего ответа в пределах даты и 5 секунд при
смене даты. Отдельные процессы не разделяют таймер; при ручных повторных
запусках соблюдайте эти паузы самостоятельно. Автоматического обхода нет.

Таймауты Requests: соединение 30 секунд, ожидание чтения 90 секунд (это не
общий предел длительности загрузки). Максимум три попытки: ожидания 15 и
30 секунд. Числовой `Retry-After` увеличивает ожидание до указанного значения,
максимум 300 секунд. Повторяются сетевые ошибки, HTTP 408/425/429/5xx,
пустой/не-HTML ответ и ошибки проверки HTML. Остальные HTTP-ответы, включая
404/410 и перенаправления, возвращаются как `page_fail` без повторов.
Перенаправления не выполняются автоматически, чтобы исключить запросы иных
ресурсов. Никакой HTTP-ответ выдачи не означает подтверждённое отсутствие PDF.

## Результат и проверки

- `records`: `doc_id`, исходный `listing_number`, фактический `source_url`,
  `title`, `description`, `query_date`. Номера всегда строки. `source_url`
  пока не является проверенным адресом PDF. `query_date` — дата запроса,
  а не извлечённая дата регистрации. Роли номеров не предполагаются.
- Идентификатор берётся только из HTTPS-ссылки с доменом `nddkr.ukrintei.ua`
  или `dir.ukrintei.ua` и путём `/view/ok/<32 hex>`. Допускается завершающий `/`.
  Ссылки с query/fragment, портом или userinfo отклоняются, чтобы не экспортировать
  возможные данные сессии. Домен фактического URL сохраняется.
- Проверяются `.my-card`, `.typeBase`, `.my-card-body`,
  `.page_control .page_info` и `.pagination`. Тип формы подтверждается
  `option[selected]` и/или фактическим способом NRAT `var typeSearch2='ok'`.
  JavaScript не исполняется; все найденные подтверждения должны совпадать.
- Повторяющиеся счётчики должны совпадать. Противоречия с карточками,
  пагинацией и фильтрами вызывают понятную ошибку. Ошибочная карточка остаётся
  в `issues` с порядковым номером и описанием; `parsing_complete=false`.
- `current_page`, `next_page_url` возвращаются, но следующий URL не запрашивается.
  Он проверяется на сохранение фильтров/сортировки/номера и нормализуется к
  `/searchdb/`; параметры сессии не экспортируются.
- `limited` обозначает явный `.limited_search`; `count_ge_1000` отдельно
  отмечает счётчик не менее 1000. Оба предупреждения включаются в `warnings`.
- `empty_day_confirmed=true` требует корректных фильтров, счётчика 0 и
  отсутствия карточек/пагинации. `parsing_complete` относится только к текущей
  странице и ничего не утверждает о полноте дня или года.

Остаётся проверить на следующих этапах: устойчивость сортировки при одинаковых
датах, варианты структуры HTML разных лет, юридическое значение даты и роли
номеров. Механизмы годового сбора и скачивания PDF здесь не реализованы.

## Структура

- `src/nrat/http.py` — таймауты, повторные попытки, паузы и история ошибок.
- `src/nrat/search.py` — модели результата, проверки и чистый разбор HTML.
- `src/nrat/__main__.py` — команда для одной явно заданной страницы.
- `tests/` — локальные тесты с искусственным HTML и подставным HTTP-клиентом.

PDF, ZIP, таблицы, HTML-ответы, логи, чекпоинты и данные сессии исключены из Git.
